# 學生手冊 —— 比賽要改什麼、要做什麼（安川 YRC1000 版）

所有指令都在終端機打（樹莓派：左上角黑色方框圖示或 Ctrl+Alt+T），先進到資料夾：
```
cd ~/Desktop/contest_2026_v10_YASKAWA
```

## 零、先弄清楚兩個通道，以及兩種通訊方式

一句話：**a 是「這是什麼顏色」，b 是「這個顏色在哪裡」。**

| 通道 | 物件在哪塊板 | 手臂做什麼 | 程式做什麼 | 程式回什麼 |
|---|---|---|---|---|
| a | 放置板（位置固定，題目指定夾哪件） | 夾起物件，舉到鏡頭與光電感測器前，發出「請辨識」後停住等結果（投票 3 秒，約第 4 秒才到） | 辨識舉在鏡頭前的物件是什麼顏色 | `IO_CODES` 那張表的 3-bit 碼 |
| b | 隨機位置放置板（每次位置不同） | job 發出「要座標」，等程式寫好再去夾 | 開場拍快照，算出每件的手臂座標 | 一件的 X、Y（照 `PICK_ORDER` 的顏色順序，不回顏色） |

每個通道各有兩種通訊方式，**兩種都是正式比賽的方式，學生自己選一種**，兩通道可以選不同的；程式兩條路同時開著，訊號會同時送到兩邊，job 讀哪一邊都可以，不用改任何設定：

| 通道 | 方式 A：接線 ／ High Speed Ethernet Server | 方式 B：Modbus TCP（埠 502） |
|---|---|---|
| a 顏色 | 繼電器 R1～R4 → 安川外部輸入；安川外部輸出 → 樹莓派 GPIO26（請辨識） | 外部輸入 `#20030`～`#20033`（同 R1～R4）或 `M000`（數字碼）；`#30030` = 請辨識 |
| b 座標 | High Speed Ethernet Server（UDP 10040）：job 把 `B001` 設 1，程式直接寫 `P001`/`P002`/`B003`；pendant 任何模式都可以 | `#30031` = 要座標；程式寫 `M010`（X×10）、`M011`（Y×10）、`M012`（0 有／1 沒）後把 `#20034` 設 ON |

- **方式 A（接線／High Speed Ethernet Server）**：照之前教材與研習營練習的做法——繼電器接外部輸入、外部輸出接 GPIO26、b 件 job 用 `B001`／`P001`。之前練好的接線與 job 流程不用改，直接上場。
- **方式 B（Modbus）**：a 件讀 `#20030`～`#20033` 或 `M000`，b 件用 `#30031`／`M010`～`M012`／`#20034`；不用接繼電器、不用接 GPIO26，一條網路線完成全部。

兩種方式的時序與編碼完全一樣（同一個執行緒同時送兩邊），選其中一種就好，不需要兩種都做。對照表在 `docs/a_channel_flow.txt` 與 `docs/yaskawa_job_interface.txt`。

## 一、你要改的五個地方（其他檔案都不要動）

| # | 檔案 | 位置 | 填什麼 | 怎麼確認填對 |
|---|---|---|---|---|
| 1 | affine_transform.py | 作答區 1：`PIXELS` / `ARMS` | 取樣工具印出的點位，至少 3 點、建議 5 點，不可排成一直線 | `python3 affine_transform.py` 印出六個參數 |
| 2 | affine_transform.py | 作答區 2：`fit()` 裡的計算（比賽會挖空） | 照《座標轉換教學》的公式手寫：Aᵀ、(AᵀA)⁻¹、T₁、T₂、回傳 2×3 矩陣 | 同上；再拿一個取樣點代進 `pixel_to_arm`，要還原出該點的手臂座標 |
| 3 | main_contest.py | 頂端 `PICK_ORDER` | 隨機位置放置板上物件的夾取順序，填顏色名（小寫）；同色兩件就寫兩次 | 啟動主程式時，快照那幾行沒有「注意」 |
| 4 | pi_gpio_controller.py | 頂端 `IO_CODES` / `FAIL_CODE` | 放置板物件的顏色 → R2 R3 R4 訊號（方式 B 把同一組當二進位寫進 `M000`：R2×4 + R3×2 + R4，預設 red=1、blue=2、green=3，失敗 7） | 第 5A 或 5B 步 |
| 5 | arm_link.py | 頂端「賽前設定」 | 安川 IP（`HOST`，兩種方式共用）；b 通道選方式 A 還要填量到的 `Z_PICK`、`Z_SAFE`（方式 B 這些由 job 自己的點位決定，可不填） | 啟動主程式後終端印出「[arm] 已連上」 |

顏色名有一條鐵則：**vision_profiles.json、PICK_ORDER、IO_CODES 三個地方的名字要一模一樣、全部小寫**。

作答區 1 還沒填完（只有 1 個點）時，`python3 affine_transform.py` 和主程式都會噴 `LinAlgError: Singular matrix`——這是正常的，代表還沒作答。`io_test.py` 借用主程式的 a 通道狀態機，這時會印 `[io] 載入 main_contest 失敗` 並把自動投票暫時關掉（畫面顯示 `[auto-off]`），按鍵測訊號照常可用；作答區 1 填好後重跑就恢復。

**安川控制器要開的東西**

| 方式 | 要開什麼 | 不開會怎樣 |
|---|---|---|
| A（b 通道 High Speed Ethernet Server） | High Speed Ethernet Server 功能（UDP 10040）；不需要 REMOTE，任何模式都可以。另外 `P001` 要先在 pendant 教成直角座標的夾取姿態點 | 終端印「沒回應」，job 等不到 `B001` 變 0；`P001` 沒教好會印「脈衝型」 |
| B（Modbus） | Modbus TCP (CPU Board) 選項；IP 與 High Speed Ethernet Server 共用 | 終端印 `[modbus] 連不上`，方式 B 的訊號全部不會到 |

**手臂端 job 怎麼寫**：a 件照 `docs/a_channel_flow.txt`（接線版在前段，Modbus 版在「同一組訊號也會經 Modbus」那段）；b 件照 `docs/yaskawa_job_interface.txt`（第三節 = 方式 A，第六節 = 方式 B）。

## 二、賽前準備（照順序做）

**第 1 步：調顏色**
```
python3 vision_tuner.py
```
把物件放到鏡頭下，用滑鼠拖 H、S、V 三條滑桿的左右把手（白色是選到的範圍），直到右半邊的 mask 只剩物件是白的、背景全黑。按 `s`，輸入顏色名（小寫），存檔。每個顏色都做一次（放置板和隨機板的顏色全部存在同一個檔）。H 的左把手可以拖到右把手右邊，這時範圍會變成頭尾兩段。按 `n` 可以叫回已存的顏色修改，`q` 離開。

**第 2 步：取點位**
```
python3 affine_sample_tool.py
```
放一件物件 → 畫面出現十字 → 按 `SPACE` 鎖定 → 把手臂夾爪尖端 Jog 到物件正上方 → 按 `c`，輸入安川 pendant 顯示的直交座標 X,Y（例 `712.3,55.8`；記下畫面上是哪個座標系）→ 換位置再做一次。點要鋪滿隨機位置放置板（四角＋中間），至少 3 點。取完按 `p`，把印出來的兩份清單抄進作答區 1。

**第 3 步：寫轉換公式（作答區 2），然後驗算**
```
python3 affine_transform.py
```
印出 `X = …*cx + …*cy + …` 和 `Y = …` 兩行就是成功。沒印出來看最後一行錯誤（對照第四節）。

**第 4 步：填 PICK_ORDER 和 IO_CODES**（改完存檔就好）

**第 4.5 步：填 arm_link.py 的賽前設定**

`HOST` 填安川的 IP（兩種方式都要）。b 通道選方式 A 的再做這段：先在 pendant 上把手臂 Jog 到「夾取姿態、剛好碰到物件」的點教成 **P001**（直角座標，座標系要和第 2 步 pendant 顯示的同一個），然後：
```
python3 arm_link.py --read-p 1
```
終端會印 P001 的全部欄位和換算後的 X Y Z，要和 pendant 顯示一致（差 1000 倍就是單位設錯，找老師）。比賽時程式只換 P001 的 X Y Z，座標系／姿態／Tool 都沿用你教的這個點，所以不用抄任何數字進程式；只要量 `Z_PICK`（碰到物件）與 `Z_SAFE`（安全通過）填進去。

**第 5 步：測通訊——照你選的方式做 5A 或 5B（兩種都用就兩個都做）**

**5A 接線**
```
python3 io_test.py
```
按 `1`～`9` 送出 IO_CODES 裡第 1～9 個顏色的訊號，到安川輸入監看畫面看接線的 DI 讀到的碼對不對；`f` 送失敗碼；`0` 全關；`r` 把鏡頭現在看到的顏色送出去（和比賽動作一樣）。b 通道（High Speed Ethernet Server）先跑 `python3 arm_link_test_yaskawa.py --selftest`（讀 B001、寫 B003、寫 P001 三項），再用 `python3 arm_link.py` 進入手動模式：job 把 `B001` 設 1，程式會把你輸入的座標寫進 `P001`。

**5B Modbus**（三個指令照順序）
```
python3 modbus_test_yaskawa.py --selftest     # 連得到 502、讀得到外部輸入/輸出、M000 寫讀 OK
python3 modbus_test_yaskawa.py                # a 通道：按數字鍵，安川輸入監看畫面看 #20030～#20033、變數畫面看 M000；
                                              #         pendant 把 #30030 設 ON，畫面的 ready 要變 ON
python3 modbus_test_yaskawa.py --coord        # b 通道：job 把 #30031 設 ON，程式寫 M010/M011/M012 並把 #20034 設 ON；
                                              #         job 把 #30031 設 OFF，#20034 要自動放下。第 3 個假座標 Y=-60 用來確認負值換算
```
三個都通過，Modbus 這條路就和比賽一樣了。

**第 6 步：練習跑一次**
```
python3 main_contest.py --practice
```
有畫面，快照的每件會標出顏色。手臂可以一直重跑，取用順序用完會自動從頭來。畫面熱鍵：`r` 重拍快照、`c` 順序歸零、`q` 離開。選方式 B 的，終端要有 `[modbus] 已連上安川 Modbus` 這一行才算就緒。

## 三、比賽當天（照順序做）

1. 手臂停在鏡頭畫面**外面**。
2. 跑正式指令：
   ```
   python3 main_contest.py --no-ui
   ```
3. 看終端機：
   ```
   [camera] index 0 開啟, 解析度 1280x720
   [b] 快照完成, 共 3 件:        ← 件數和顏色要對
       #0 red ...
   [modbus] 已連上安川 Modbus 192.168.0.1:502       ← 方式 B 要看到這行；方式 A 印「連不上」可以不理
   [arm] High Speed Ethernet Server … 與 Modbus … 兩條路都在等 job 要座標
   [main] === 階段二: 可以按手臂了 ===
   [arm] 已連上安川, 等 job 把 B001 設成 1          ← 方式 A 要看到這行；方式 B 印「沒回應」可以不理
   ```
   **看到「階段二」以及你那條路的「已連上」才按手臂。**
4. 比賽中不要碰程式。手臂每要一次座標，終端會印「[b] 給 red → 手臂(…)」和 `[arm] 第 N 件 …`（隨機板）；每次舉物件到鏡頭前會印「[a] 判定 … → 送 IO」（放置板）。
5. 結束後 Ctrl+C 離開。

## 四、終端最後一行 → 原因 → 怎麼辦

| 最後一行 | 原因 | 怎麼辦 |
|---|---|---|
| `LinAlgError: Singular matrix` | 作答區 1 點太少或排成一直線；或作答區 2 寫錯 | 重取點位／檢查公式 |
| `ValueError: matmul ... mismatch` | PIXELS 和 ARMS 點數不一樣 | 兩份清單數一數 |
| `io_test.py` 印 `[io] 載入 main_contest 失敗`，畫面顯示 `[auto-off]` | 作答區 1 還沒抄或抄錯 | 和通訊無關；按鍵測訊號照常，作答區 1 修好後重跑就恢復自動投票 |
| `[camera] 試過 [0..5] 都讀不到畫面` | 相機沒插好，或被別的程式佔住 | 插好；關掉還開著的 tuner／sample tool |
| `[camera] 注意: 不是 1280x720` | 相機解析度不對，點位會全錯 | 換回同一台相機再啟動 |
| `找不到 vision_profiles.json` | 還沒存顏色 | 做第 1 步 |
| `[b] 注意: PICK_ORDER 有 'xxx'，但快照裡沒有` | 顏色名寫錯，或快照時物件被擋住 | 對名字；手臂移出畫面按 `r` 重拍（練習模式） |
| 手臂一直讀到 `B003`=1（或 `M012`=1） | 該顏色已經給完，或 PICK_ORDER 用完 | 正式比賽這是正常結束；練習用 `--practice` |
| 終端印 `沒回應 (逾時/連不上)` | 方式 A：樹莓派沒連上安川（IP 錯、網線、High Speed Ethernet Server 沒開） | 檢查 `arm_link.py` 的 `HOST` 與網線；只用方式 B 的可以不理 |
| 終端印 `P001 是脈衝型位置變數` | 方式 A：`P001` 還沒在 pendant 教成直角座標點 | 做第 4.5 步 |
| `--read-p 1` 的 X Y Z 和 pendant 差 1000 倍 | 位置資料單位設定不對 | 找老師改 `arm_link.py` 的 `POS_UNIT_MM` |
| 終端印 `[modbus] 連不上 …:502` | 方式 B：Modbus TCP 選項沒開、或 IP 不對 | 請老師確認選項；只用方式 A 的可以不理 |
| job 等 `#20034` 一直等不到 | job 設的是 `#30030`（那是 a 通道）不是 `#30031`；或上一輪的 `#30031` 沒放下 | 改對編號；每件結束要把 `#30031` 設 OFF |
| job 讀到的 X 或 Y 變成三萬多 | `M010`/`M011` 是 16-bit 有號數，負值以二補數存 | job 讀到 ≥ 32768 減 65536（用 `--coord` 的 Y=-60 驗） |
| 手臂動了但位置不對 | 方式 A：`P001` 教的座標系和取點位時 pendant 的不一樣；方式 B：job 基準點位的座標系不對；或點位不是在這台手臂上取的 | 對座標系；重取點位 |

## 五、四個絕對不要

- **相機動過不重取點位**——相機位置一變，作答區 1 全部作廢。
- **啟動主程式時手臂在畫面內**——快照會拍到手臂，物件被擋住。
- **顏色名不一致**——`Red`、`red `（多空白）都算不一樣。
- **沿用別台手臂的數字**——`Z_PICK`、`Z_SAFE`、`P001` 的姿態、取樣點位全部要在這台安川上重量重教。
