//===== 一、賽前控制器設定 (不做這兩項, 樹莓派什麼都寫不進去) =====
//
//  1) 開啟 Ethernet Server 功能                              (手冊 8.2.1)
//       a. 按住 {主選單 (Main Menu)} 開機 → 進入維護模式
//       b. 安全模式設為「MANAGEMENT MODE (管理模式)」
//       c. 主選單 → {SYSTEM} - {SETUP} - "OPTION FUNCTION"
//       d. 選 "NETWORK FUNCTION SETTING" 的 DETAIL
//       e. 把 "ETHERNET SERVER" 設成 "STANDARD" 或 "EXPAND"
//       f. 按 [Enter] → 確認對話框 → {YES}
//
//  2) 開啟 command remote —— 兩個動作, 少一個都不算開           (手冊 8.2.2 → 1.2.3)
//       a. 主選單 → {IN/OUT} → {PSEUDO INPUT SIG} → "CMD REMOTE SEL" 設為【啟用】
//       b. programming pendant 的 mode key 轉到 [REMOTE]
//       沒開的話, 樹莓派終端會印:
//         [arm] SAVEV 失敗: 錯誤碼 2100 未設定 command remote (CMD REMOTE SEL 要啟用, mode key 轉 REMOTE)
//
//  3) 網路: 樹莓派與控制器同網段; Ethernet Server 用 TCP 埠 80 (手冊 8.4.2)。
//       控制器 IP 填進 arm_link.py 頂端的 HOST。
//
//  4) 五分鐘自我檢查 (手冊 8.4.3 自己給的方法):
//       telnet <控制器IP> 80
//       輸入 CONNECT Robot_access          (正常設定下不會回顯)
//       輸入 HOSTCTRL_REQUEST RSTATS 0
//       看到  OK: RSTATS  與  194,0  就表示功能正常。
//     或直接用本專案工具讀一個位置變數:  python3 arm_link.py --read-p 10


//===== 二、變數介面 (編號固定, 不開放修改) =====
//
//   變數   誰寫    值與意義
//   -----  ------  --------------------------------------------------------
//   B001   job     1 = 我要座標
//          樹莓派  0 = 資料已經寫好了, 你可以動了
//
//   B003   樹莓派  0 = 有座標, P001 / P002 可以用
//                  1 = 沒座標 (該顏色已給完、或 PICK_ORDER 用完) → 這一件跳過
//
//   P001   樹莓派  夾取點        X,Y 由視覺算出, Z = Z_PICK
//   P002   樹莓派  夾取點正上方  X,Y 同上,      Z = Z_SAFE
//
//   不回顏色: 順序是選手在 main_contest.py 的 PICK_ORDER 排的, 第 N 段 b 子流程拿到的
//   一定是 PICK_ORDER[N-1] 那個顏色, 放置點位直接接死即可。
//
//  【寫入順序的保證】樹莓派固定照 P001 → P002 → B003 → B001=0 寫。
//  job 只要「等到 B001 變 0」, 其他三個一定已經是這一輪的新值。
//  【B003=1 時 P001 不會被改寫】—— 還留著上一件的值, 所以 job 一定要先判 B003 再動。


//===== 三、每一件 b 物件的 job 流程 =====
//
//  ┌ 1. B001 = 1
//  ├ 2. 等 B001 == 0 (建議逾時 10 秒)     ← 樹莓派每 0.3 秒輪詢一次, 正常 1 秒內就回
//  ├ 3. 判 B003:  1 → 這件跳過, 接下一件;  0 → 往下走
//  ├ 4. 移到 P002 (正上方, Z = Z_SAFE)
//  ├ 5. 直線下降到 P001 (夾取點, Z = Z_PICK)
//  ├ 6. 關夾爪, 稍等讓它確實夾住
//  ├ 7. 直線抬起回 P002
//  ├ 8. 移到題目區 3 對應的預教點位 (第 N 段 = PICK_ORDER[N-1] 的顏色)
//  └ 9. 開夾爪, 抬起離開 → 回主流程接下一件
//
//  ※ job 自己用相對移動下降 (不需要 P002) 時, 可把 arm_link.py 的 WRITE_APPROACH 設 False。


//===== 四、整體 flow 範例 (題目要求 5 件: a, b, b, a, b) =====
//
//   Start
//    ├─ 起始姿態 + 電爪開合一次           (依題目卷評分規範)
//    ├─ 第 1 件 ── a 子流程 (見 a_channel_flow.txt)
//    ├─ 第 2 件 ── b 子流程 (上面第三節 1~9 步)
//    ├─ 第 3 件 ── b 子流程
//    ├─ 第 4 件 ── a 子流程
//    ├─ 第 5 件 ── b 子流程
//    └─ 回起始姿態
//
//   a 與 b 的先後由 job 的排列決定; b 內部「先夾哪個顏色」由 PICK_ORDER 決定。
//   job 裡有幾段 b 子流程, PICK_ORDER 就排幾個顏色。


//===== 五、賽前一次性的量測 (都要在安川實機上量) =====
//
//  1) 座標系 / 姿態 / 工具號碼
//       pendant 上把手臂 Jog 到「夾取姿態、剛好碰到物件」的點, 教成 P010, 然後:
//           python3 arm_link.py --read-p 10
//       印出 座標系, X, Y, Z, Rx, Ry, Rz, Type, Tool (手冊 8.3.2 SAVEV 回覆格式 2),
//       並提示可抄進 arm_link.py「賽前設定」的哪幾行。
//
//  2) 兩個 Z 高度: Z_PICK = 夾爪碰到物件的高度; Z_SAFE = 安全通過物件上方的高度。
//
//  3) affine 取樣點位
//       affine_sample_tool.py 按 c 時輸入的 X,Y 是 pendant 顯示的直交座標, 印出的
//       PIXELS/ARMS 手寫進 affine_transform.py。
//       ★ pendant 顯示的是哪個座標系, arm_link.py 的 COORD_FRAME 就要填哪一個,
//         不一致會準確地跑到錯的地方。


//===== 六、常見問題 =====
//
// Q: 終端一直印錯誤碼 2100?
// A: 第一節第 2 項的兩個動作要都做到 (CMD REMOTE SEL 啟用 + mode key 轉 REMOTE)。
//
// Q: job 卡在「等 B001 變 0」?
// A: 看樹莓派終端 [arm] 那行: 印錯誤碼 → 對照說明 (手冊表 11-1); 印「沒回應 (逾時)」→
//    IP、網線、80 埠, 用第一節第 4 項的 telnet 步驟確認。
//
// Q: 手臂動了但位置不對?
// A: COORD_FRAME 要和 affine 取樣時 pendant 顯示的座標系同一個; 點位必須是在這台手臂上取的。
//
// Q: 姿態怪 / 到不了位?
// A: POSE_TYPE (手冊 LOADV 的 Data-11) 要照 --read-p 讀回實機的值填。
//
// Q: 錯誤碼 2010 / 2070 / 2080?
// A: 手臂動作中 / 伺服關 / 模式不對 —— 手臂狀態問題, 不是通訊問題 (手冊表 11-1)。
