//   第六節:     Modbus 那條路 (樹莓派寫 M010~M012, job 自己填位置變數); 兩條路同時開著, job 擇一使用

//===== 一、賽前控制器設定 =====
//
//  1) 開啟 High Speed Ethernet Server 功能 (UDP 埠 10040)
//       pendant 任何模式 (TEACH / PLAY / REMOTE) 都能讀寫變數, 不需要 command remote。
//       開啟方式與是否為選購功能, 以安川提供的說明為準。
//
//  2) 把 P001 教成直角座標的夾取姿態點
//       pendant 上把手臂 Jog 到「夾取姿態、剛好碰到物件」的點, 教成 P001 (座標系要和 affine 取樣時 pendant 顯示的一樣)。
//       樹莓派每次寫座標都是「讀回 P001 現值 → 只換 X Y Z → 寫回」, P002 用同一筆資料換 Z;
//       所以 P001 的座標系 / 姿態 / Tool 就是比賽時手臂實際用的。P001 若是脈衝型, 程式會拒絕寫入並提示。
//
//  3) 網路: 樹莓派與控制器同網段; 控制器 IP 填進 arm_link.py 頂端的 HOST (與 Modbus 共用)。
//
//  4) 自我檢查 (不需要 job):
//       python3 arm_link.py --read-p 1          讀回 P001 全部欄位與換算後的 mm / 度, 要和 pendant 顯示一致
//       python3 arm_link_test_yaskawa.py --selftest   讀 B001、寫 B003、寫 P001 三項


//===== 二、變數介面 (編號固定, 不開放修改) =====
//
//   變數   誰寫    值與意義
//   -----  ------  --------------------------------------------------------
//   B001   job     1 = 我要座標
//          樹莓派  0 = 資料已經寫好了, 你可以動了
//
//   B003   樹莓派  0 = 有座標, P001 / P002 可以用
//                  1 = 沒座標 (該顏色已給完、或 PICK_ORDER 用完) → 這一件跳過
//
//   P001   樹莓派  夾取點        X,Y 由視覺算出, Z = Z_PICK
//   P002   樹莓派  夾取點正上方  X,Y 同上,      Z = Z_SAFE
//
//   不回顏色: 順序是選手在 main_contest.py 的 PICK_ORDER 排的, 第 N 段 b 子流程拿到的
//   一定是 PICK_ORDER[N-1] 那個顏色, 放置點位直接接死即可。
//
//  【寫入順序的保證】樹莓派固定照 P001 → P002 → B003 → B001=0 寫。
//  job 只要「等到 B001 變 0」, 其他三個一定已經是這一輪的新值。
//  【B003=1 時 P001 不會被改寫】—— 還留著上一件的值, 所以 job 一定要先判 B003 再動。


//===== 三、每一件 b 物件的 job 流程 =====
//
//  ┌ 1. B001 = 1
//  ├ 2. 等 B001 == 0 (建議逾時 10 秒)     ← 樹莓派每 0.3 秒輪詢一次, 正常 1 秒內就回 (UDP, 無連線數額度)
//  ├ 3. 判 B003:  1 → 這件跳過, 接下一件;  0 → 往下走
//  ├ 4. 移到 P002 (正上方, Z = Z_SAFE)
//  ├ 5. 直線下降到 P001 (夾取點, Z = Z_PICK)
//  ├ 6. 關夾爪, 稍等讓它確實夾住
//  ├ 7. 直線抬起回 P002
//  ├ 8. 移到題目區 3 對應的預教點位 (第 N 段 = PICK_ORDER[N-1] 的顏色)
//  └ 9. 開夾爪, 抬起離開 → 回主流程接下一件
//
//  ※ job 自己用相對移動下降 (不需要 P002) 時, 可把 arm_link.py 的 WRITE_APPROACH 設 False。


//===== 四、整體 flow 範例 (題目要求 5 件: a, b, b, a, b) =====
//
//   Start
//    ├─ 起始姿態 + 電爪開合一次           (依題目卷評分規範)
//    ├─ 第 1 件 ── a 子流程 (見 a_channel_flow.txt)
//    ├─ 第 2 件 ── b 子流程 (上面第三節 1~9 步)
//    ├─ 第 3 件 ── b 子流程
//    ├─ 第 4 件 ── a 子流程
//    ├─ 第 5 件 ── b 子流程
//    └─ 回起始姿態
//
//   a 與 b 的先後由 job 的排列決定; b 內部「先夾哪個顏色」由 PICK_ORDER 決定。
//   job 裡有幾段 b 子流程, PICK_ORDER 就排幾個顏色。


//===== 五、賽前一次性的量測 (都要在安川實機上量) =====
//
//  1) 座標系 / 姿態 / 工具號碼
//       不用抄進程式: 把夾取姿態點教成 P001 (第一節第 2 項), 程式會沿用它的座標系 / 姿態 / Tool。
//       用  python3 arm_link.py --read-p 1  讀回來和 pendant 對照一次, 確認單位換算 (X Y Z 0.001 mm, 角度 0.0001 度)。
//
//  2) 兩個 Z 高度: Z_PICK = 夾爪碰到物件的高度; Z_SAFE = 安全通過物件上方的高度。
//
//  3) affine 取樣點位
//       affine_sample_tool.py 按 c 時輸入的 X,Y 是 pendant 顯示的直交座標, 印出的
//       PIXELS/ARMS 手寫進 affine_transform.py。
//       ★ pendant 顯示的是哪個座標系, P001 就要教在哪個座標系 (程式沿用 P001 的座標系),
//         不一致會準確地跑到錯的地方。


//===== 六、Modbus 那條路 (與第三節二選一; 選這條就不需要 High Speed Ethernet Server) =====
//
//  控制器要開 Modbus TCP (CPU Board) 選項, IP 與 High Speed Ethernet Server 共用同一個 (192.168.0.1:502)。
//  位址對照 (實機已驗證: 外部輸入 #20030 起 ↔ Modbus coil 0 起; 外部輸出 #30030 起 ↔ discrete input 0 起; M000 ↔ holding register 0):
//
//    訊號                方向            意義
//    外部輸出 #30031     job → 樹莓派    設 ON = 我要座標 (a 通道的 ready 是 #30030, 不同點)
//    M010                樹莓派 → job    X × 10 (單位 0.1 mm, 16-bit 有號數)
//    M011                樹莓派 → job    Y × 10
//    M012                樹莓派 → job    0 = 有座標, 1 = 沒座標 (該顏色已給完或 PICK_ORDER 用完, 這件跳過)
//    外部輸入 #20034     樹莓派 → job    設 ON = M010~M012 已寫好 (a 通道用 #20030~#20033, 不同點)
//
//  每一件 b 物件的 job 流程:
//  ┌ 1. 外部輸出 #30031 = ON
//  ├ 2. 等外部輸入 #20034 == ON (建議逾時 10 秒)   ← 樹莓派每 0.1 秒讀一次, 正常 1 秒內就回
//  ├ 3. 判 M012:  1 → 外部輸出 #30031 = OFF, 這件跳過, 接下一件;  0 → 往下走
//  ├ 4. GETREG 把 M010、M011 讀進整數變數 (例 I010、I011), 再除 10 (或 × 100) 換成 mm 的位置元素
//  │    ※ 16-bit 有號: 讀回 ≥ 32768 代表負值, 要減 65536 (GETREG 若已當有號數處理就不用減; 用 --coord 測一次 Y=-60 確認)
//  ├ 5. 以預教的基準點位為底, SETE 把 X、Y 填進第 1、2 元素 (Z、姿態、座標系、工具沿用基準點位) → 得到 P001 (夾取點)
//  │    與 P002 (正上方, Z 加安全高度)
//  ├ 6. 外部輸出 #30031 = OFF                       ← 樹莓派看到才會放下 #20034, 下一次請求才讀得到新值
//  ├ 7. 移到 P002 → 直線下降到 P001 → 關夾爪 → 抬起回 P002
//  ├ 8. 移到題目區 3 對應的預教點位 (第 N 段 = PICK_ORDER[N-1] 的顏色)
//  └ 9. 開夾爪, 抬起離開 → 回主流程接下一件
//
//  ※ 這條路樹莓派只給 X、Y; Z_PICK / Z_SAFE / 姿態 / 座標系都由 job 自己的基準點位決定, 不經過 P001。第 5 步的位置元素單位 (0.001 mm) 與 SETE / GETREG 的寫法請以 YRC1000 作業指令手冊為準。
//
//  驗證 (不開相機): python3 modbus_test_yaskawa.py --coord
//    job 把 #30031 設 ON, 終端會印寫進去的 M010 / M011; 到變數畫面看 M010~M012, 到 I/O 畫面看 #20034。
//    假座標的第 3 點 Y = -60 用來確認負值換算。


//===== 七、常見問題 =====
//
// Q: job 卡在「等 B001 變 0」?
// A: 看樹莓派終端 [arm] 那行: 印「沒回應 (逾時/連不上)」→ IP、網線、High Speed Ethernet Server 沒開;
//    印「status=… 附加碼=…」→ 控制器拒絕, 查 High Speed Ethernet Server 手冊的錯誤碼表。
//
// Q: 終端印「P001 是脈衝型位置變數」?
// A: P001 還沒教成直角座標點 (第一節第 2 項); 教好後重跑。
//
// Q: 手臂動了但位置不對?
// A: P001 的座標系要和 affine 取樣時 pendant 顯示的同一個; 點位必須是在這台手臂上取的;
//    用 --read-p 1 確認換算後的 X Y Z 和 pendant 一致 (差 1000 倍就是單位設錯)。
//
// Q: 姿態怪 / 到不了位?
// A: 程式沿用 P001 的 form (姿態) 與 Tool; 把 P001 重新教成正確的夾取姿態。
//
// Q: (Modbus) job 等 #20034 一直等不到?
// A: 樹莓派終端沒印「[modbus] 已連上」→ Modbus TCP 選項或 IP; 有印但沒反應 → job 設的是不是 #30031 (不是 #30030)。
//    也可能上一輪的 #30031 沒放下: 樹莓派要看到 #30031 OFF 才會收回 #20034。
//
// Q: (Modbus) 負座標變成三萬多?
// A: M010 / M011 是 16-bit 有號數以二補數寫入; job 讀到 ≥ 32768 要減 65536。
